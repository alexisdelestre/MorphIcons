    Intégrer les pictos dans une app

    Le moteur s’intègre une seule fois par app, puis il gère tous les pictos et toutes les transitions : changez le nom du picto affiché, il anime. Les pictos eux-mêmes vivent dans un fichier de données, morph-icons.json, maintenu par les designers. Mettre à jour les pictos = remplacer ce fichier.

    Comment ça marche

    Chaque picto est fait d’exactement 3 lignes, sur une grille de 24 (épaisseur 2, bouts arrondis, dans l’esprit de Phosphor). Comme tous les pictos ont la même structure, n’importe lequel peut se transformer en n’importe quel autre : chaque ligne glisse vers une ligne du picto d’arrivée.

    Moins de 3 traits ? Les lignes en trop sont masquées : elles deviennent un point invisible au centre. Pendant une transition, une ligne masquée « pousse » depuis le centre, ou s’y résorbe en s’effaçant.

    Même forme, autre angle ? Rotation. Les 4 flèches, les 4 chevrons, plus/croix, télécharger/envoyer sont des groupes de rotation : une seule forme, plusieurs angles. Entre deux pictos d’un même groupe, la forme tourne (toujours par le plus court chemin) au lieu de se déformer.

    Quelle ligne va où ? Le moteur choisit automatiquement l’appariement qui fait le moins voyager les points : l’ordre dans lequel vous dessinez les lignes n’a pas d’importance. Quand le résultat ne plaît pas à l’œil, une correction manuelle impose l’appariement pour cette paire précise.

    Corriger une transition

    1. Playground : choisissez la paire (cliquez dans la Revue rapide ou utilisez les menus De / Vers).
    2. Cochez Afficher les lignes et utilisez le curseur : chaque ligne a sa couleur, ● marque son début, ○ sa fin, et les pictos de départ / d’arrivée apparaissent en filigrane.
    3. Cliquez Corriger cette transition…, puis choisissez pour chaque ligne de départ la ligne d’arrivée qu’elle doit devenir (et son sens). L’aperçu se met à jour en direct.
    4. Enregistrer dans le brouillon. La correction vaut dans les deux sens (A → B et B → A).
    5. Si la transition reste moche quel que soit l’appariement, c’est souvent le dessin qu’il faut ajuster : passez par l’éditeur.

    Ajouter ou modifier un picto

    1. Éditeur › + Nouveau : donnez un nom (minuscules et tirets, ex. arrow-up-right). Ce nom est celui qu’utiliseront les devs : choisissez-le bien.
    2. Dessinez avec 3 lignes maximum. Glissez les points, masquez les lignes inutiles. Restez dans la marge de 2 (cadre pointillé).
    3. Si c’est une variante tournée d’un picto existant (ex. une flèche en diagonale), préférez + Variante tournée dans un groupe : elle tournera proprement.
    4. Vérifiez les transitions avec Tester et la Revue rapide depuis votre picto.

    Renommer ou supprimer un picto casse les apps qui l’utilisent : prévenez les devs.

    Publier une nouvelle version

    Vos modifications restent dans un brouillon local (dans ce navigateur) tant qu’elles ne sont pas publiées. Pour publier :

    1. Télécharger morph-icons.json dans la barre du brouillon. Le numéro de version est incrémenté automatiquement.
    2. Sur GitHub, ouvrez le dépôt, puis Add file › Upload files et déposez le fichier (il remplace l’ancien). Décrivez le changement, puis Commit changes.
    3. Cette page est mise à jour en une minute environ. Abandonnez alors votre brouillon.
    4. Prévenez les devs : « morph-icons.json vN disponible ». Ils remplacent le fichier dans chaque app, sans toucher au code.

    Le fichier est formaté avec un picto par ligne : sur GitHub, l’onglet des différences montre exactement ce qui a changé.

    Pour les mainteneurs du moteur

    Le moteur de référence est core/morph-core.ts. Les versions Swift, Kotlin et Dart en sont des traductions ligne à ligne. Elles sont vérifiées par les fixtures de conformité (conformance/fixtures.json) : 420 transitions calculées par la référence, que chaque version doit reproduire à 10-4 près. Le CI GitHub (.github/workflows/ci.yml) lance toutes ces vérifications à chaque commit.

    npm test                     # tests de la référence + fichiers générés à jour
node scripts/build.mjs       # après une modification de core/morph-core.ts

    Les designers qui ne modifient que morph-icons.json n’ont rien à lancer.
